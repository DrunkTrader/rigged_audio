# Testing strategy

## Layers

1. **Pure unit:** WAV parsing, source hashing, path safety, config fingerprints, state transitions, preset mix behavior.
2. **Integration:** atomic store migrations, duplicate reuse, mock engine, cancellation, failure injection, export manifests.
3. **Audio correctness:** deterministic PCM fixtures; frame count, sample rate, channels, finite samples, peak/clipping and alignment assertions.
4. **Renderer component/workflow:** keyboard navigation, accessible labels, import/error/processing/complete states, mix controls.
5. **End-to-end:** Electron app import → run → reopen → play → export using mock engine and a tiny generated fixture.
6. **Packaging smoke:** native-runner build/launch per OS; no model download.
7. **Performance:** named fixture, duration/format/sample rate, hardware, model, device, precision, wall time, peak RAM, and method recorded in `docs/testing/benchmarks.md` when the real engine exists.

## Deterministic fixture

The test fixture is a short stereo 44.1 kHz PCM WAV generated by the test script. The mock engine uses the same engine interface as real adapters and has no network or GPU dependency. Real-model tests are opt-in and isolated from routine CI.

## Failure injection

Cover corrupt/truncated WAV, missing source, disk-write failure, invalid output, worker non-zero exit, timeout, cancellation at each phase, duplicate start, restart after temp artifact, and schema migration. A failed test must inspect the persisted record and filesystem, not just an exception string.

## Accessibility and security gates

Run keyboard-only core flow, focus-visible assertions, accessible-name checks, contrast audit, dependency scan, secret/path redaction checks, and offline network verification before release.
