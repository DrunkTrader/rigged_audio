# Feature parity and differentiation matrix

Priority uses MoSCoW. Acceptance criteria are deliberately testable. “Reference evidence” points to observed README/source behavior, not copied implementation.

| Capability             | Reference evidence                                                           | Rigged Audio decision                                                           | Priority  | Acceptance criteria                                                                         | Implementation phase |
| ---------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------- | --------- | ------------------------------------------------------------------------------------------- | -------------------- |
| Local audio import     | `src/main/index.ts` picker; `pipeline.ts` local job                          | Adopt as a product requirement; drag/drop is first-class                        | Must      | WAV can be picked or dropped, metadata is shown, source is preserved                        | 3                    |
| Multiple audio formats | `library.ts` extension list + FFmpeg conversion                              | Improve substantially with decoder capability reporting and explicit conversion | Should    | Unsupported/corrupt input produces actionable error; supported formats documented per build | 4                    |
| Source metadata        | `pipeline.ts` WAV duration and yt-dlp metadata                               | Adopt with richer codec/sample-rate/channel fields                              | Must      | Duration, sample rate, channels, size, codec visible before processing                      | 3/4                  |
| Duplicate detection    | `pipeline.ts` model/stem cache reuse                                         | Improve using source SHA-256 + engine/config fingerprint                        | Must      | Same source/config reuses valid artifacts and never overwrites a different source           | 3                    |
| YouTube search         | README; `youtube.ts`; `searchYouTube`                                        | Defer to a consented adapter; local workflow remains complete offline           | Could     | No YouTube code is required for local MVP; adapter has explicit policy gate                 | 6                    |
| YouTube URL import     | README; yt-dlp subprocess                                                    | Defer pending legal/terms review and network threat model                       | Could     | Documented no-network default and no bypass behavior                                        | 6                    |
| Four-stem separation   | README; Demucs path                                                          | Adopt as core engine contract                                                   | Must      | Engine returns vocals/drums/bass/other with aligned valid WAV fixtures                      | 3; real model 4      |
| Two-stem separation    | Supported by suitable models in ecosystem, not a dedicated reference UI path | Adopt through engine registry                                                   | Should    | Registry can expose vocals/accompaniment without UI rewrite                                 | 4/6                  |
| Extra instruments      | `htdemucs_6s` and target selection                                           | Improve with capability-driven target list                                      | Should    | Guitar/piano appear only when engine declares support                                       | 6                    |
| Model selection        | README/settings and `resolveEngine`                                          | Adopt explainable recommended preset plus manual override                       | Must      | Recommendation shows model, expected trade-off, and reason                                  | 4/6                  |
| CPU fallback           | `env.ts`, `pipeline.ts`                                                      | Adopt; detect and verify actual execution                                       | Must      | Failed accelerator probe falls back or blocks with diagnostic detail                        | 4                    |
| CUDA/MPS/ROCm          | `env.ts` probes and installs                                                 | Adopt behind capability probes, no detection-only claims                        | Should    | UI labels backend as verified only after compute test                                       | 4/7                  |
| Model lifecycle        | First-use downloads and optional weights in `env.ts`                         | Improve into catalog/checksum/version states                                    | Must      | Partial/corrupt/incompatible/ready states are distinct and tested                           | 4/7                  |
| Progress phases        | `JobStage` and JSON child output                                             | Adopt with persisted phase/state                                                | Must      | UI shows queue, prepare, inference, validate, export and failures                           | 3/5                  |
| Cancellation           | `cancelJob` kills process and removes directory                              | Adopt with cooperative cancellation and cleanup validation                      | Must      | Cancellation leaves no success record or partial artifact marked valid                      | 3/5                  |
| Crash recovery         | No durable job state observed                                                | Improve substantially                                                           | Must      | Restart marks interrupted jobs recoverable or failed, never successful                      | 3/7                  |
| Synchronized playback  | Web Audio anchor clock in `engine.ts`                                        | Adopt with one master clock and drift measurement                               | Must      | Mute/solo/volume and seeking affect all stems from one timeline                             | 3/5                  |
| Waveform navigation    | Stem lanes and decoded buffer drawing                                        | Improve with bounded peak cache                                                 | Should    | Long-file rendering does not require full PCM in renderer                                   | 5/7                  |
| Stem mix controls      | Renderer lanes, mute/solo/volume/pan                                         | Adopt with accessible controls                                                  | Must      | Keyboard and screen-reader labels expose each control and state                             | 3/5                  |
| Presets                | All/Karaoke/Acapella/Drums + Bass                                            | Reimplement with original names and recommendation context                      | Should    | Preset changes audible mix state and is persisted per project                               | 5                    |
| WAV export             | Main-process copy/export                                                     | Adopt atomic export + manifest                                                  | Must      | Selected/all stems export to valid WAV and manifest                                         | 3/5                  |
| Lossless formats       | Reference primarily WAV; AAC optional                                        | Improve with FLAC evaluation; WAV is baseline                                   | Should    | Export format never silently changes sample rate/normalization                              | 5/6                  |
| Library                | JSON song index and song directories                                         | Reimplement with versioned local project records                                | Must      | Search/sort/reopen survives restart and source move is recoverable                          | 3/5                  |
| Pan persistence        | `pan.json`                                                                   | Adopt in project mix state, with schema migration                               | Could     | Pan survives restart and is clamped to safe range                                           | 5                    |
| Settings               | Engine toggles, hide video, export format                                    | Reimplement around local-first storage and diagnostics                          | Should    | Storage, backend, precision, theme, telemetry controls work                                 | 5/7                  |
| Offline operation      | README says offline after setup                                              | Adopt as explicit invariant                                                     | Must      | Installed mock/real engine can process with network blocked                                 | 3/4/7                |
| Telemetry              | Anonymous install ping                                                       | Exclude by default                                                              | Must      | No telemetry request is made unless user opts in later                                      | 2/7                  |
| Updates                | `electron-updater` and release workflows                                     | Adopt signed release channel with rollback docs                                 | Should    | Update path is documented and never runs unverified artifacts                               | 7                    |
| Smart presets          | Not present as explainable product feature                                   | Improve substantially                                                           | Should    | Recommendation includes hardware/source/quality rationale                                   | 6                    |
| A/B quality compare    | Optional model variants, not core reference flow                             | Defer until real engine evaluation exists                                       | Could     | Only enabled when two valid outputs and measurements exist                                  | 6                    |
| Output diagnostics     | Basic file existence checks observed                                         | Improve with alignment/clipping/NaN checks                                      | Must      | Warnings include severity and reproducible values                                           | 4/5                  |
| Folder batch           | Background/parallel jobs observed; no full folder workflow verified          | Adopt resource-aware batch                                                      | Should    | Folder import preserves relative paths and retries safe failures                            | 6                    |
| Project bundle         | Not observed                                                                 | Adopt after core persistence                                                    | Could     | Bundle includes manifest and selected outputs without surprise copies                       | 6                    |
| Plugin engines         | Fixed scripts observed                                                       | Defer; stable registry is the seam                                              | Won't MVP | Adapter contract documented before third-party loading is enabled                           | 7                    |
